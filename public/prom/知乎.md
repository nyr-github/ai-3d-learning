# AI 3D Learning Platform - 一套完整的3D模型在线展示解决方案

## 背景

最近AI图像生成3D模型的技术发展很快，从单张图片生成3D GLB模型已经成为现实。但在实际使用过程中，我发现了一个被忽视的问题：**模型生成后的展示和分享**。

## 问题陈述

作为一个开发者，我观察到以下现象：

1. **AI工具链成熟，但展示环节缺失**
   - 豆包、Midjourney 等工具可以生成高质量图像
   - 混元3D、Tripo 等可以将图像转为3D模型
   - 但是，缺乏简单易用的在线展示方案

2. **3D Web开发门槛过高**
   - Three.js 学习曲线陡峭
   - WebGL 编程需要专业知识
   - 性能优化、响应式适配等问题需要大量时间

3. **教育场景需求未被满足**
   - 传统教学依赖平面图片展示3D结构
   - 学生难以通过2D图片理解空间关系
   - 缺乏交互式的学习工具

基于这些痛点，我决定开发一个开源的3D在线展示平台，并提供完整的AI工作流文档。

## 技术方案

### 技术栈选择

- **前端框架**：Next.js 16 (App Router + 静态导出)
- **3D渲染**：Three.js + React Three Fiber + Drei
- **模型压缩**：DRACO (减少50-80%文件体积)
- **图片优化**：WebP格式 (比PNG/JPG小30-50%)
- **样式系统**：Tailwind CSS v4
- **部署**：GitHub Pages (零服务器成本)

### 核心架构

```
AI工作流：
豆包(图像生成) → 混元3D(图像转3D) → 模型优化 → 网站部署

数据架构：
JSON配置 → 通用Entity3D模型 → 自动渲染
```

### 关键技术实现

#### 1. 智能模型加载系统

采用状态驱动 + 缓存策略：

```typescript
// 加载状态机
idle → downloading → parsing → completed

// 缓存策略
- 内存缓存：已加载模型保存在Map中
- 预加载：预测用户下一个可能查看的模型
- 错误处理：优雅处理网络问题和格式错误
```

#### 2. 响应式布局设计

**桌面端**：三列可调布局（侧边栏 + 3D查看器 + 信息面板）
**移动端**：全屏3D查看器 + 滑动手势调出面板

#### 3. 性能优化策略

- 自适应DPR：`[1, 2]` 平衡清晰度和性能
- 阴影贴图：1024x1024 质量/性能平衡
- DRACO解码器：预加载并配置
- 环境贴图：HDR studio lighting预设

## 使用指南

### 快速开始

```bash
# 克隆仓库
git clone <repository-url>
cd ai-3d-learning

# 安装依赖
pnpm install

# 开发模式
pnpm dev

# 构建静态站点
pnpm build
```

### 添加自定义模型

1. 将GLB文件放入 `public/models/`
2. 将预览图（WebP）放入 `public/images/`
3. 在 `data/projects/` 下配置数据文件
4. 运行优化脚本：
   ```bash
   pnpm optimize:glb ./public/models
   pnpm convert:webp ./public/images
   pnpm update:model-sizes
   ```

### 部署

项目使用Next.js静态导出，可部署到：
- GitHub Pages（内置Actions工作流）
- Vercel
- Netlify
- 任意CDN

## 技术细节补充

### 关于DRACO压缩

DRACO是Google开发的3D几何压缩算法，可以显著减少GLB文件体积。本项目：

- 预置DRACO解码器文件（`public/draco/`）
- GLTFLoader自动配置DRACOLoader
- 支持`.glb`和`.gltf + .bin`格式

### 关于模型优化

使用glTF Transform进行模型优化：

```bash
# 优化流程包括：
1. 纹理重编码为WebP
2. 应用DRACO几何压缩
3. 移除冗余数据
4. 优化网格结构
```

### 关于静态导出

Next.js静态导出的关键配置：

```javascript
// next.config.js
const nextConfig = {
  output: 'export',
  // 动态路由需要generateStaticParams
};
```

对于动态路由 `project/[slug]`，需要在服务端组件中实现：

```typescript
export function generateStaticParams() {
  return projects.map((project) => ({
    slug: project.slug,
  }));
}
```
